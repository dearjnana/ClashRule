# 使用与回退

本次是本地规则包整理。根目录原有 INI、规则和其他部署文件保持原状，优化版使用新的 `profiles/` 入口。上传仓库本身不会把旧入口切换成新版。

## 文件入口

| 用途 | 文件 |
|---|---|
| 推荐优化版 | [MyRuleClash_Plus_V1.optimized.ini](../profiles/MyRuleClash_Plus_V1.optimized.ini) |
| 完全展开版，排查规则集合下载问题 | [MyRuleClash_Plus_V1.expanded.ini](../profiles/MyRuleClash_Plus_V1.expanded.ini) |
| 原入口 | [MyRuleClash_Plus_V1.ini](../MyRuleClash_Plus_V1.ini) |
| Gemini 网页 / App / AI Studio 规则 | [Gemini.list](../rules/ai/Gemini.list) |

两个新版入口都面向 Mihomo。验证使用 SubConverter-Extended v1.9.6 和 Mihomo v1.19.31；不能把这份验证外推为所有旧 Clash 核心或转换服务都兼容。

## 先上传，再转换，最后试用

1. 将整个本地规则包上传到仓库，至少包含 `profiles/`、`rules/`、`providers/`、`templates/`；保留审计和来源文件便于维护。
2. 当前文件中的 Raw 前缀已统一到 `dearjnana/ClashRule` 的 `main`。若先用测试分支，必须将前缀切到该分支，否则会读到尚未更新的 main。
3. 在已有转换服务中使用新版 INI 地址，转换参数设置 `target=clash`、`expand=true`，下载为本地 `converted.yaml`。这一步保留两份显式原生 rule-provider，其余小文件展开。
4. 运行下面的整理命令生成一个新 YAML。**此步必需**：SubConverter-Extended 会重建策略组，直接依赖基础模板里的 `proxy-groups` 会丢失分组；它也不能从 INI 保留全部原生字段。
5. 在使用的 Mihomo 核心上执行配置检查，备份当前配置及选择记录后，将新 YAML 作为一个新配置导入 OpenClash，再由使用者手动切换试用。

```powershell
python -m pip install -r tools/requirements.txt
python tools/finalize.py converted.yaml ready.yaml
mihomo -t -d ./validation-cache -f ./ready.yaml
```

`finalize.py` 从转换结果中的 `x-clashrule-native-groups` 恢复原生分组，删除这个辅助字段，仅写入新的输出文件，不访问路由器、不重启服务、不修改输入文件。输出文件已存在时会拒绝覆盖。实际订阅生成的 YAML 含机场订阅地址或凭据，应留在本机，不能上传到公开仓库。

不要将未整理的 `converted.yaml` 直接投入使用。转换兼容分组里的 `REJECT` 只是占位，整理后才改为原生 `empty-fallback: REJECT`，并恢复 Gemini 默认节点、健康检查状态码等字段。

若继续使用自动订阅更新，需要在每次转换后执行同等整理；只手动整理一次不会覆盖后续更新。目前提供的是可复核的离线流程，没有替你安装新的路由器更新钩子。现有历史钩子是否等价，应单独核对，不能假定它会完整处理新格式。

## 修改仓库 / 分支前缀

手动统一替换两个新 INI 和两个基础模板中的 Raw 前缀即可；不要修改 `audit/original/` 中的来源地址。也可以从快照重建：

```powershell
python tools/build.py --base-url https://raw.githubusercontent.com/dearjnana/ClashRule/refs/heads/你的测试分支/
python tools/verify.py
```

`build.py` 会重建优化产物并覆盖对这些产物的手工编辑。需要长期保存的调整应写入生成器或维护的新源文件；原始快照只读保留。脚本不会联网刷新上游。

## Gemini 选择与验证

新版默认路径为 `🎐 Gemini → 🇺🇸 Gemini MESL美国 → [MESL]🇺🇸 美国 01`。MESL 美国 01 不存在时选择该组第一条匹配节点；一个美国节点也没有时阻断。其他服务的手动选择能力保留。

Mihomo 若已有选择缓存，缓存可能优先于新的默认值。切换后应在面板核对实际链路，再分别验证网页版发起对话、手机 App 发起对话和附件/语音等所需功能。不要只依据延迟或首页 HTTP 200 判断 Gemini 业务可用性。规则只能控制已识别域名的出口；账号地区、节点出口信誉、设备私有 DNS、IPv6 接管、QUIC 等仍可能影响结果。

共同的 Google 登录、`apis.google.com`、FCM 推送由各自 Google / FCM 组处理。没有将整个 `googleapis.com` 或 `gstatic.com` 强制塞进 Gemini。若真实登录或 App 对话仍有漏项，应按该次连接记录补具体域名。

## 回退

试用前保留当前能工作的 YAML、订阅入口和面板选择。出现问题时，在 OpenClash 切回原配置并恢复对应选择；不要只把 INI 链接改回去却继续运行已生成的新 YAML。

原 INI 和 44 个依赖的完整快照在 `audit/original/`，SHA-256 在 `manifest.json` 和 `source-metadata.json`。两个新增规则集合也有展开版可作对照；若只有集合下载异常，可用完全展开版转换并整理后试用。

## 重跑隔离集成测试

从官方发布页面准备 SubConverter-Extended v1.9.6 完整目录与 Mihomo v1.19.31 可执行文件。前者需要附带 `base/pref.example.ini` 等资源。执行：

```powershell
python tools/integration_test.py --subconverter-dir "你的转换器目录" --mihomo "你的mihomo可执行文件"
```

测试使用合成节点和公开测试密码，只监听 `127.0.0.1:25591`、`:25592`、`:25593`，结束时关闭所启动的进程；请先保证端口未被其他程序使用。结果存入被 Git 忽略的 `.test-work/`。首次核心检查可能下载 GEOIP 数据库，不访问你的实际机场或路由器。
