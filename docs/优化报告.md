# 规则整改结果

更新日期：2026-09-21。

## 仓库结构

移除原始快照、原始片段、旧 README、空占位文件、重复旧配置和无引用图片。规则统一维护在 `rules/`；策略组、优先级、基础设置位于 `config/`。生成器直接读取这些维护文件，不再依赖原始档案。

52 份规则源中，44 份参与主配置，其余用于独立客户端或个人补充，未擅自全部加入主配置。维护规则与按顺序去重后的输出职责分离，避免修改源文件后被旧快照覆盖。

## 已修正的问题

- Gemini 网页/应用与 AI Studio/API 分别交给两个服务组，均排在通用 Google 与 AI 前面。新的 API 专用列表优先匹配，原 Gemini 列表保留已有条件兼容旧订阅。
- 取消 MESL 美国 Gemini 测试组。三个客户端按同一份官方地区数据生成筛选：网页或 Android 的普通账号地区并集为 241，API 为 229；不限机场。完整清单与服务差异见 [Gemini 地区说明](Gemini地区说明.md)。
- 修复 `.oaistatic.com` 错误精确匹配；将 Google 推送和共享 Cloudflare 从 AI 抢占规则中移除。
- Telegram 统一为纯条件列表，不再使用混有 PROXY 动作的 YAML 片段，也不延续未经证实的 `91.108.0.0/16` 宽范围补充。
- Adobe 放行例外及 Pixiv 必要例外优先；同步修正 Clash Party 覆写中的错误顺序。
- 同文件重复、被后缀覆盖的子域名、CIDR 主机位和个人 DNS 列表重复已整理。
- MiniMax 补充规则保留域名后缀，移除过宽关键词。
- 八份旧 INI 统一迁移到当前维护入口，不再保留旧版本副本。
- 代理补充规则的 12 条正则统一维护在 `rules/network/ProxyLite.list`，保留转义和原有顺序。OpenClash 与 Android 的 INI 仅保留 `ProxyGFW` 原生集合引用和 `ProxyLite.list` 链接；4,303 个域名继续使用原生集合，主规则数不变。

## 性能与验证

主配置使用原生中国 IP 与代理域名集合，减少展开规则量；最新数量见 [生成索引](仓库文件索引.md)。80 个策略组保留原生过滤、空组拒绝、按需健康检查和选择记忆。两个 Gemini 组使用手动选择，不增加定时测速。

离线验证覆盖域名、IP 边界和重点服务回归，并检查去重前后策略链、IP 解析选项和原生集合覆盖一致。隔离转换测试验证三个输出通过 Mihomo 配置检查，并在 OpenClash 与 Android 运行配置中检查 Gemini 两组跨机场筛选、网页/API 差异、空组行为和规则集合加载。

Clash Party 验证覆盖 70 个策略组、43 个真实规则集、节点列表/节点集合/缺少 MESL/没有可用地区四种场景、全部地区旗帜筛选、首次下载与 17 个实际连接规则命中。地区代码和所有别名另经静态回归检查。

隔离转换使用 SubConverter-Extended v1.9.7，配置检查使用 Mihomo v1.19.31。OpenClash、Android 和展开配置均通过；Android 与路由器共用分流规则，基础监听和健康检查周期分别适配。

这些验证不访问真实机场节点，也不代表 Gemini 账号的地区资格或服务可用性。部署与规则整理步骤见 [使用说明](使用与回退.md)。
