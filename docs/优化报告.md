# V1 规则优化报告

审计日期：2026-09-20。原仓库提交：`2319d8b3a5e5df0e0370c3d29136cb2c5301430c`。下载 44 个依赖：43 份规则、1 份基础模板；主 INI 单独保存。下载无缺项，所有 SHA-256 已复核。

## 范围与结果

逐条扫描 15,398 条源规则，为每条保留来源、行号、原文、正规化结果、处理状态及原因，见 [rule-review.jsonl](../audit/rule-review.jsonl)。这表示语法、重复、覆盖和优先级审计，并不表示对 15,398 条域名逐一进行了联网访问或业务验收。

优化规则文件合计 14,699 条；加上内联兜底等规则，完全展开为 14,702 条。原生规则集合版主规则表为 2,842 条，较优化后的完全展开版减少约 80.7%。其余匹配条件仍在两份原生集合里，并未丢弃：ChinaIP 为 7,109 个网段，ProxyGFW 为 4,303 个域名后缀。

主规则表缩短有利于减少线性检查，但集合仍占用内存。没有把条数下降等同于 CPU、延迟或内存按同比例改善，也没有在现网跑压力测试。

## 分组与性能

保留原有 79 个分组并增加 Gemini MESL 美国选择组，总计 80 个。地区筛选增加国旗、完整国家名称和有词边界的地区缩写，排除亚美尼亚等“美国”误匹配。对脱敏节点名称快照的匹配统计见 [node-filter-summary.json](../audit/node-filter-summary.json)，其中 Gemini MESL 美国组匹配 14 个节点；本仓库不包含实际节点地址或订阅凭据。

43 个含动态节点筛选的分组使用 `empty-fallback: REJECT`。只有空组才用 REJECT，正常自动选择组不再把 REJECT 当作测速候选。Gemini 首选 MESL 美国 01，避免其他机场自动组选入结果；有历史选择缓存时仍须核对实际选择。

自动组统一 HTTPS 检测地址、300 秒周期、lazy、5 秒超时，url-test 保留 150 ms 容差；统一 URL 有助于核心复用同一 Provider 的检查任务，不声称严格“一节点只有一次请求”。健康检查只判断连接，不判断 Gemini 账号能否发消息。

国内网段与 GFW 后缀分别使用 ipcidr / domain 原生集合，每日检查更新，文件缓存路径固定。其余规则保留可审查的文本顺序。原基础模板中不被 Mihomo 使用的 CFW 字段和过时实验选项不再带入新模板；OpenClash 的 DNS、接管和防火墙应继续由现有管理配置负责。

转换器会重建策略组，因此必须执行 [finalize.py](../tools/finalize.py) 恢复模板保留的原生字段。该步骤只生成新的本地文件，具体操作和自动更新限制见 [使用与回退](使用与回退.md)。为避免上传仓库后现网自动更新时误用未整理配置，新版只放在 profiles/ 下，根目录正在被引用的入口没有替换。

- 分组名称无重复、无缺失引用、无循环。
- SubConverter-Extended v1.9.6 实际转换两个入口，再整理原生字段；Mihomo v1.19.31 对两份最终配置执行 -t 均通过。

机器结果见 [verification.json](../audit/verification.json) 和 [integration-results.json](../audit/integration-results.json)。上述等价检查针对已明确记录的修正之后的规则；Gemini 补充、错误关键词收窄等本来就是有意改变，不能表述为与原配置完全相同。

本轮没有部署新包到运行中的 OpenClash，也未重新验收真实账号的手机对话；节点地区、账号限制、DNS / IPv6 接管不能仅靠静态规则保证。
